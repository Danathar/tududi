# Fork delta: upstream files this fork changes

`Danathar/tududi` is a fork of `chrisvel/tududi`. Most of what the fork adds
lives in files upstream does not have (`.claude/`, `policies/`, `tests/`,
`.github/prompts/`, `scripts/check-policies.mjs`, and `docs/` pages such as
this one). This page lists the other kind of change: edits to
**upstream-owned files**, meaning any file `chrisvel/tududi` also has, wherever
it lives. Backend modules, frontend components, upstream's backend tests,
`README.md`, `package.json` and upstream's workflows all count.

Each upstream sync merges upstream's changes on top of these edits, so a
conflict lands in exactly these files. The page exists so that whoever runs
the sync can tell, for each conflicting file, which fork PR changed it and
why, and then decide: upstream fixed the same thing (take theirs and drop the
row), upstream changed something nearby (combine both), or upstream never
touched it (keep ours). See
[`sync-upstream.prompt.md`](../.github/prompts/sync-upstream.prompt.md).

## Keeping it current

- **Add a row** in the same pull request that changes an upstream-owned file.
  A PR that touches only files upstream does not have adds nothing. Sync PRs
  add no rows for the upstream changes they bring in.
- **Upstream** is `fork only`, or `fixed upstream in <commit>` once a sync
  shows upstream made the same change; drop that row in the sync PR.
- When a sync moves code a row covers, refresh that row's file list in the
  sync PR.
- Keep the reason to one line; the PR holds the detail.
- `node scripts/check-fork-delta.mjs [<upstream-ref>]` checks this page against
  `git diff <upstream-ref> HEAD`: it fails on a changed or deleted
  upstream-owned file that no row names, and on a named file that is now the
  same as upstream. With no ref it uses the upstream commit of the last sync
  merge; during a sync, pass `upstream/main` (or the release tag).

The rows below were backfilled from `git log` for every PR merged since the
fork started (#1) that changed an upstream-owned file. Sync merges are left
out.
